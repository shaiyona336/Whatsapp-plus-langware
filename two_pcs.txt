================================================================================
 RUNNING TERMCHAT ON TWO PCs
 (desktop + laptop, both connected to your phone's hotspot)
================================================================================

THE IDEA
--------
One PC is the SERVER - it runs the backend (port 8080) and the frontend
(port 3000). The other PC needs only a BROWSER and Node.js (to run the tiny
agent). In this guide the desktop is the server and the laptop is the guest.

IMPORTANT: the demo needs NO internet. The hotspot is only used as a Wi-Fi
switch so the two PCs can reach each other. No traffic leaves the phone.

Terms used below:
  <IP>  = the desktop's address on the hotspot network, e.g. 10.170.247.121.
          It can CHANGE every time the desktop reconnects to the hotspot,
          so always use the value printed by start-lan-server.ps1 (Part 2).


================================================================================
PART 1 - ONE TIME ONLY: open the Windows firewall on the DESKTOP
================================================================================

Why: Windows blocks INCOMING connections from other machines by default, and
on "Public" networks (a phone hotspot counts as Public) it blocks everything.
These two rules permanently allow other machines to reach ports 8080 and 3000.

1. Click Start, type: powershell
2. RIGHT-CLICK "Windows PowerShell" -> "Run as administrator" -> Yes.
3. Paste these two lines (this is what "the two firewall commands" means):

   netsh advfirewall firewall add rule name="TermChat 8080" dir=in action=allow protocol=TCP localport=8080 profile=any
   netsh advfirewall firewall add rule name="TermChat 3000" dir=in action=allow protocol=TCP localport=3000 profile=any

4. Each should print "Ok.". Close the window. You never need this again
   (the rules survive reboots).

To undo later (optional):
   netsh advfirewall firewall delete rule name="TermChat 8080"
   netsh advfirewall firewall delete rule name="TermChat 3000"


================================================================================
PART 2 - EVERY TIME: start the server side on the DESKTOP
================================================================================

1. Connect BOTH PCs to the same phone hotspot.

2. On the desktop, open PowerShell (normal, not admin) in the project folder:
     cd C:\Users\shai\Desktop\projects\Whatsapp-plus-langware

3. Run the start script:
     .\start-lan-server.ps1

   (If PowerShell refuses to run scripts, run this once and retry:
     Set-ExecutionPolicy -Scope CurrentUser RemoteSigned )

   What it does:
     - Detects the desktop's LAN IP and PRINTS it. WRITE THIS <IP> DOWN -
       the laptop needs it.
     - Opens a window running the backend on 0.0.0.0:8080 (0.0.0.0 means
       "listen on the real network too", not just localhost).
     - Opens a window running the frontend on 0.0.0.0:3000 with the right
       env vars (see "what the script sets" at the bottom).

4. Wait until the frontend window shows:  "Ready in ..."

5. Start YOUR agent (this is what lets commands run on the desktop when you
   share a folder). In a new terminal:
     cd C:\Users\shai\Desktop\projects\Whatsapp-plus-langware\agent
     node agent.js alice

   Use the same name you will type on the login screen. You should see:
     [agent] connected to ws://127.0.0.1:8080/agent/ws as "alice"


================================================================================
PART 3 - ON THE LAPTOP
================================================================================

1. CONNECTIVITY CHECK FIRST - in the laptop's browser open:
     http://<IP>:8080/users
   Expected: []  (or a JSON list of users)
   If this times out -> go to PART 5. Nothing else can work until this does.

2. Open the app:
     http://<IP>:3000
   Log in as a DIFFERENT name, e.g.:  bob

3. Start bob's agent on the laptop (needed only if the laptop will SHARE its
   own terminal; skip if the laptop only runs commands on the desktop).
   Requirements: Node.js 22+ and the single file agent\agent.js
   (copy it over on a USB stick, or clone the repo - it has NO dependencies,
   no npm install needed).

   In cmd:
     set AGENT_WS_URL=ws://<IP>:8080/agent/ws && node agent.js bob
   Or in PowerShell:
     $env:AGENT_WS_URL='ws://<IP>:8080/agent/ws'; node agent.js bob

   Expected:  [agent] connected to ws://<IP>:8080/agent/ws as "bob"


================================================================================
PART 4 - THE DEMO
================================================================================

1. Desktop (alice): click "bob" in contacts -> chat opens. Send a message,
   see it appear instantly on the laptop.

2. Desktop (alice): in "Shared terminals" enter a folder that exists on the
   DESKTOP, e.g.:
     C:\Users\shai\Desktop\projects\Whatsapp-plus-langware\test_commands
   Click Share.

3. Laptop (bob): the terminal panel appears. Type:  dir  -> the command runs
   ON THE DESKTOP (alice's agent) and the output shows on BOTH screens.

4. Now the reverse - Laptop (bob): share a folder that exists on the LAPTOP.
   Desktop (alice): run  dir  in bob's terminal -> it executes ON THE LAPTOP.

   That's the whole point demonstrated: same conversation, two terminals,
   every command runs on the machine of the person who SHARED that terminal.


================================================================================
PART 5 - TROUBLESHOOTING (when the laptop can't reach http://<IP>:8080/users)
================================================================================

Work top to bottom - each step isolates one layer:

1. WRONG IP? Hotspots often assign a new IP on reconnect. Re-run
   .\start-lan-server.ps1 on the desktop (or run: ipconfig) and use the
   current Wi-Fi IPv4 address.

2. SERVERS ACTUALLY UP? On the DESKTOP browser, check
   http://localhost:8080/users and http://localhost:3000 work locally.

3. FIREWALL? Temporarily disable it to test. On the desktop, ADMIN PowerShell:
     netsh advfirewall set allprofiles state off
   Retry step 1 of PART 3 on the laptop, then IMMEDIATELY re-enable:
     netsh advfirewall set allprofiles state on
   If it worked while off -> the PART 1 rules are missing/wrong. Re-add them.

4. STILL DEAD -> the phone hotspot has "client isolation" (some phones block
   hotspot clients from talking to each other; many, incl. most Xiaomi/Redmi,
   allow it - so this is the last suspect, not the first).

   FALLBACK THAT ALWAYS WORKS (no router needed):
   Make the DESKTOP itself the hotspot:
     Windows Settings -> Network & Internet -> Mobile hotspot -> On
   Connect the LAPTOP to the desktop's hotspot (name/password shown on that
   settings page). Now the two PCs talk directly - nothing can isolate them.
   Re-run .\start-lan-server.ps1 (the desktop's IP on its own hotspot is
   usually 192.168.137.1) and redo PART 3 with that IP.
   Remember: the demo needs no internet, so it doesn't matter if the
   laptop has no web access while on the desktop's hotspot.

   This fallback is also the answer AT THE INTERVIEW if the office Wi-Fi
   blocks peer-to-peer: "my machine will broadcast a hotspot, connect to it."

Other known issues:

- Frontend window shows "EADDRINUSE ... port 3000": a leftover node process
  is holding the port. In PowerShell:
    Get-NetTCPConnection -LocalPort 3000 -State Listen
  note the OwningProcess number, then:
    Stop-Process -Id <that number> -Force
  and start again. (Same recipe for 8080 if needed.)

- Chat works but commands answer "(no agent connected for 'alice' ...)":
  the agent for that user isn't running, or was started with a DIFFERENT
  username than the web login. Restart it with the matching name.

- Terminal panel loads but commands hang ~30s then time out: agent was
  started pointing at the wrong AGENT_WS_URL. It must use ws://<IP>:8080
  from the laptop (localhost only works on the desktop itself).


================================================================================
APPENDIX - what start-lan-server.ps1 actually sets (for understanding/manual runs)
================================================================================

Backend:   .venv\Scripts\uvicorn main:app --host 0.0.0.0 --port 8080
           (default host would be 127.0.0.1 = unreachable from the laptop)

Frontend:  NEXT_PUBLIC_WS_URL=ws://<IP>:8080
             The laptop browser's WebSocket must dial the DESKTOP's IP -
             "localhost" inside the laptop's browser means the laptop itself.
             Baked in when the dev server starts, so restart after IP changes.
           ALLOWED_DEV_ORIGIN=<IP>
             Next 16's dev server returns 403 for its /_next/* files when the
             page was opened from a non-localhost address, unless that origin
             is allow-listed (wired up in next.config.ts).
           npx next dev -H 0.0.0.0 -p 3000

Note: REST API calls don't need any env var - the browser calls /api/* on
whatever host it loaded the page from, and Next proxies that to the backend
on the same machine (127.0.0.1:8080).
